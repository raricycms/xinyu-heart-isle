## 一、先厘清一件事：我们做的不是"心理治疗产品"

在写下任何功能之前，必须先明确这个产品的**能力边界**。心理类产品最容易出的问题不是功能不够，而是**越界**——
让用户误以为一个网页能替代诊断、替代医生、替代一个真实的人。

因此本项目的第一条产品原则是：

> **心屿是一个"自我了解与情绪调节的辅助工具"，不是医疗服务，不做诊断，不承诺疗效。**

这条原则会具体落成三条硬性设计约束，贯穿全文：

| 约束 | 具体表现 |
| --- | --- |
| **不做诊断** | 量表结果只呈现"分数落在哪一段"，不出现"你有抑郁"这类表述；每个结果页固定声明"这不是诊断" |
| **不替代专业帮助** | 所有结果页、工具页、首页底部都有通往 `/safety` 的入口 |
| **危机必须能兜住** | 一旦量表出现高危信号（如 PHQ-9 第 9 题 > 0），强制弹出求助热线区块，不折叠、不弱化 |

## 二、目标用户与使用场景

### 2.1 三类用户

| 用户类型 | 特征 | 核心诉求 | 最可能用的功能 |
| --- | --- | --- | --- |
| **A. 自我探索者**（占比最大） | 18–35 岁，好奇自己的状态，愿意做测试，但不愿去医院 | "我最近是不是有点问题？" | 量表、心情签到、趋势回看 |
| **B. 情绪过载者** | 正处在焦虑、失眠、崩溃边缘，来得很急 | "我现在很难受，马上做点什么" | 情绪工具箱、危机页、沙盘 |
| **C. 支持者/寻找资源者** | 想帮自己或身边的人找到靠谱资源 | "该去哪里求助？" | 资源地图、危机页 |

### 2.2 五个关键场景（设计时的"靶子"）

1. **深夜失眠时**，用户打开手机，不想刷短视频，想搞清楚自己怎么了 → 量表 + 身体扫描
2. **焦虑发作、心跳很快** → 一屏内就能开始 4-7-8 呼吸，不需要读三页说明
3. **说不清但很难受** → 赛博沙盘，把东西摆出来，不用会表达
4. **想改变一个反复出现的负面想法** → 思维记录表，四步表单带着走完
5. **真的撑不住了** → 危机页，三秒内看到能打的电话

> 场景 2 和 5 决定了信息架构：**安全入口必须常驻顶栏，急救型工具必须在两次点击内触达。**

### 3.2 功能优先级（MoSCoW）

| 优先级 | 功能 | 理由 |
| --- | --- | --- |
| **Must**（V1 必须有） | 量表 + 结果解读、危机页、心情签到、资源地图 | 产品的存在理由；危机页是安全底线 |
| **Must** | 数据本地化 + 导入导出 | 无后端时唯一的数据尊严保障 |
| **Should**（V1 已实现） | 赛博沙盘、呼吸/着陆练习、思维记录、我的记录时间线 | 差异化与真实使用价值 |
| **Could**（V1.1） | 深呼吸自定义节奏、量表趋势对比、沙盘模板、导出 PDF | 提升留存，非必需 |
| **Won't**（V1 明确不做） | 用户账号、社区/评论区、AI 心理对话、在线咨询撮合、积分打卡 | 每一项都会引入后端、合规与伦理风险；AI 对话尤其容易越界成为"假治疗师" |

### 3.3 量表设计（V1 内置 5 份）

| 量表 | 全称 | 题数 | 量程 | 计分要点 | 用途 |
| --- | --- | --- | --- | --- | --- |
| PHQ-9 | 患者健康问卷-9 | 9 | 0–27 | 0–3 四级；**第 9 题为自伤意念，>0 触发危机提示** | 抑郁情绪自评 |
| GAD-7 | 广泛性焦虑量表-7 | 7 | 0–21 | 0–3 四级 | 焦虑水平自评 |
| PSS-10 | 知觉压力量表 | 10 | 0–40 | 0–4 五级；含 4 道反向计分题 | 主观压力感受 |
| ISI | 失眠严重指数 | 7 | 0–28 | 0–4 五级；含临床参考切点 | 睡眠质量 |
| RSES | 自尊量表 | 10 | 10–40 | 1–4 四级；含 5 道反向计分题 | 自我价值感 |

**设计要点：**

- **反向计分必须正确**：`total += (min + max - value)`，这是量表单页最容易写错也最影响可信度的地方。
- **分级区间必须连续且不重叠**：用闭区间 `min <= total <= max` 查找，且首尾覆盖整个量程。
- **结果页三段式**：① 分数与区间 → ② 这个区间通常意味着什么（中性描述）→ ③ 现在可以做的 3 件事。
- **分级色调只用 4 档语义色**（good / watch / warn / alert），不滥用红色。

### 3.4 赛博沙盘：为什么值得做

传统沙盘（Sand Tray）是表达性艺术治疗的一种形式，价值在于**绕过语言**。
网页版沙盘不追求治疗效力，而追求三件事：

1. **低门槛表达**——不用会画画，拖拽一个象征物就有意义
2. **外化与距离**——把"我很难受"变成"这个黑影在角落"，人就有了观察它的位置
3. **可回看**——快照保存后，隔一周再看，常会看到自己都没注意的变化

**关键设计决策：** 不评判、不分析。系统不告诉用户"你摆成这样说明你……"，只提供**开放式提问**
（"这个摆件离你最远，它代表什么？"）。解释权始终在用户手里。

### 3.5 情绪工具箱：按"情绪强度"而非"理论流派"分组

工具按**用户当下的状态**组织，而不是按 CBT/正念/叙事疗法分类：

| 分组 | 适合状态 | 工具 | 时长 |
| --- | --- | --- | --- |
| **立即安抚** | 心跳快、喘不上气、脑子空白 | 4-7-8 呼吸、方块呼吸、5-4-3-2-1 着陆、身体扫描 | 1–8 分钟 |
| **认知梳理** | 反复想同一件事、钻牛角尖 | 思维记录表（情境→自动思维→证据→平衡想法） | 10 分钟 |
| **日常记录** | 状态平稳，想积累觉察 | 担忧时间、三件好事 | 5–15 分钟 |

### 3.6 明确不做的事（以及为什么）

| 不做的功能 | 原因 |
| --- | --- |
| 用户账号 / 云同步 | 需要后端与合规评估；心理健康数据的泄露后果远重于普通数据 |
| 社区、评论区、树洞 | 无人运营的倾诉社区极易变成互相强化负面情绪的地方，且需要危机审核能力 |
| AI 心理对话 | 最容易越界的功能。模型无法识别真实危机，也无法承担误判后果 |
| 在线咨询撮合 | 涉及医疗资质与平台责任，超出 V1 范围 |
| 打卡积分 / 连签奖励 | 把自我照顾变成 KPI，反而制造压力 |

## 四、信息架构与交互原则

### 4.1 导航结构

顶栏固定 6 项：**首页 / 心理量表 / 赛博沙盘 / 情绪工具箱 / 资源地图 / 我的记录**，
右上角常驻红色语义的 **「我需要帮助」** 直达 `/safety`。
页脚再次链接危机页与「关于与边界」。

> 之所以把「我的记录」放进主导航：它是让用户"回来"的锚点。没有记录，工具站是一次性消耗品。

### 4.2 五条交互原则

1. **永远可见的退出**——任何练习/作答都随时可以停下，且停下不被评判（"随时可以停下，这已经很好了"）
2. **危险入口零摩擦**——危机页从任何页面最多两次点击可达；热线支持一键复制与 `tel:` 直拨
3. **不制造焦虑**——不用红色警报轰炸、不用倒计时压迫、不推送"你可能得了……"
4. **尊重减弱动效**——提供 `reducedMotion` 偏好，同时也是 `prefers-reduced-motion` 的兜底
5. **结果永远附带下一步**——只说"你有问题"而不给出可执行动作，是残忍的

### 4.3 视觉语言

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 底色 | 暖沙 `#f6f3ec` + 极淡径向渐变 | 纯白在夜间刺眼，暖色让人放松 |
| 主色 | 雾青 `#4d7d70` | 低饱和的绿蓝，接近自然与医疗的中间地带，不冷硬 |
| 辅助色 | 暖陶 `#d39d68` | 用于提醒与温度感 |
| 标题字 | 衬线（Songti / Noto Serif SC） | 衬线带来"被认真对待"的感觉 |
| 正文 | 系统无衬线，15px / 1.7 | 中文长文的舒适行高 |
| 圆角 | 8–26px，按钮全圆 | 柔化界面，降低"系统感" |
| 阴影 | 极轻（4%–10% 不透明度） | 避免浮夸 |
| 动效 | 0.18–0.45s，`cubic-bezier(0.22,0.61,0.36,1)` | 缓慢、有呼吸感 |

## 五、技术架构

### 5.1 选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | **Vite 8** | 冷启动快，配置少，产物为纯静态文件 |
| UI | **React 19** | 生态成熟，`useSyncExternalStore` 让本地存储订阅变得干净 |
| 语言 | **TypeScript（strict）** | 量表计分这类逻辑最怕静默错误，类型是防线 |
| 路由 | **react-router-dom 7** | 标准方案，支持嵌套路由与布局共享 |
| 样式 | **纯 CSS + 设计令牌（CSS 变量）** | 零依赖、零构建开销；心理健康产品不需要复杂设计系统 |
| 状态 | **localStorage + `useSyncExternalStore`** | 无后端场景下最简单可靠的方案，且天然支持跨标签页同步 |

> **刻意不引入的依赖**：UI 组件库、图表库、状态管理库、动画库、日期库。
> 理由：本项目图表只有一个柱状趋势和几个刻度尺，值不得一个 50KB 的图表库；
> 依赖越少，这个站点越可能在五年后还能被打开。

### 5.3 数据模型（核心）

```ts
// 所有记录共享 { id, at } 基类，便于统一时间线聚合
interface BaseRecord { id: string; at: string }

interface MoodEntry extends BaseRecord {
  mood: 1|2|3|4|5; energy: 1|2|3|4|5; tags: string[]; note?: string
}

interface ScaleResult extends BaseRecord {
  scaleId: string
  answers: Record<string, number>   // 保存原始作答，便于回溯与将来重算
  total: number
  dimensionScores?: Record<string, number>
  levelId: string
}

interface SandboxItem {
  id: string; symbolId: string
  x: number; y: number              // 归一化 0~1，跨屏幕尺寸一致
  scale: number; rotation: number; z: number; note?: string
}
interface SandboxSnapshot extends BaseRecord {
  title: string; items: SandboxItem[]; sceneId: string
  reflection?: string; prompts?: string[]
}

interface ToolSession extends BaseRecord {
  toolId: string; durationSec?: number; payload?: Record<string, unknown>
}

interface JournalEntry extends BaseRecord {
  kind: 'gratitude' | 'thought-record' | 'free-write'
  title: string; content: string; mood?: number
}
```

**两个关键设计决策：**

1. **`answers` 保存原始分值而非折算后分值**。反向计分题的折算发生在计分时，
   这样将来若修正计分规则，历史记录可以重算，不会作废。
2. **沙盘坐标归一化到 0~1**。否则换个屏幕尺寸，精心摆好的布局就全乱了。

### 5.4 存储层设计

```
localStorage keys:
  xinyu.moods          MoodEntry[]
  xinyu.scaleResults   ScaleResult[]
  xinyu.sandbox        SandboxSnapshot[]
  xinyu.toolSessions   ToolSession[]
  xinyu.journal        JournalEntry[]
  xinyu.preferences    Preferences
```

**难点与解法**：`useSyncExternalStore` 要求 `getSnapshot()` 在无变化时返回**同一引用**，
否则 React 会无限重渲染。直接 `JSON.parse` 每次都会产生新数组。解法是维护一份
`snapshotCache: Map<key, value>`，只在写入或 `storage` 事件（跨标签页）时失效。

```ts
function getSnapshot<T>(key: string, fallback: T): T {
  if (snapshotCache.has(key)) return snapshotCache.get(key) as T;
  const value = readJSON<T>(key, fallback);
  snapshotCache.set(key, value);
  return value;
}
```

这带来了一个**编码约定**：`useCollection` 返回的是不可变快照，禁止原地修改数组元素，
一切修改都必须走 `add / upsert / update / remove`。

### 5.5 数据所有权

无后端意味着"数据不在我们手里"是天然成立的，但仍需给用户**可控感**：

- **导出**：全量打包成 `{ app:'xinyu', version, exportedAt, data }`，下载为 JSON
- **导入**：校验 `app === 'xinyu'` 后写入，防止用户误导入无关文件
- **清空**：二次确认，并提示先导出

## 六、安全与伦理设计（本项目的重点章节）

### 6.1 危机识别与兜底

| 触发条件 | 系统行为 |
| --- | --- |
| PHQ-9 第 9 题得分 > 0 | 结果页顶部强制展示 alert 级求助区块，不折叠 |
| 任量表命中 `tone === 'alert'` 分级 | 同上 |
| 用户点击顶栏「我需要帮助」 | 直达危机页，首屏即热线 |
| 任何页面的记录为空且有反复低落迹象 | 「我的记录」页底部展示温和的求助建议 |

危机区块固定包含：

- 全国统一心理援助热线 **12356**（24 小时）
- 北京心理危机研究与干预中心 **010-82951332**（24 小时）
- 希望 24 热线 **400-161-9995**（24 小时）
- 通往 `/safety` 的完整求助页

### 6.2 文案规范（写作红线）

| ✗ 不要写 | ✓ 应该写 |
| --- | --- |
| "你有中度抑郁" | "你的得分落在 10–14 分区间，这个区间通常提示近期情绪负担较重" |
| "建议立即就医"（对轻度） | "如果这些感受持续两周以上，可以考虑找专业人士聊聊" |
| "坚持打卡才能变好" | "记录只是给自己看的，断了也没关系" |
| "你太敏感了" | （不做任何此类归因） |

**统一语气**：温和、平视、不说教、不承诺、不恐吓。

### 6.3 内容可信度

- 量表题干与分级基于公开发表的常用中文版本整理，**页面上明确声明"仅供自评参考"**
- 热线与资源链接**每条都带 `verifiedAt` 核验日期**
- 在 `helplines.ts` 顶部与「关于」页明确提示：**号码可能变更，上线前必须逐个核验**
- 对不确定的链接采取"宁可不写"策略

### 6.4 技术侧隐私

- **零网络请求**：代码中不存在任何 `fetch` / `XHR` / `sendBeacon` 上报用户数据
- 唯一的外部请求是用户主动点击的外链（`target="_blank" rel="noopener noreferrer"`）
- 无第三方统计、无广告、无 Cookie 追踪
- 不收集任何可识别身份的信息（无姓名、手机号、身份证字段）

> **验证过程中修复的真实缺陷**（记录在此，避免重复踩坑）：
> 1. `usePreferences()` 每次返回新对象，导致 `useSyncExternalStore` 判定状态持续变化而陷入死循环，
>    **整站在浏览器里是白屏**——类型检查和构建都发现不了这类问题，只有真实浏览器渲染能暴露。
>    修复：存储层对每个 key 缓存快照，只在写入 / 跨标签页更新时失效。
> 2. 首页心情签到的 5 个表情按钮在 `flex-wrap` 下被压缩成异形排列。修复：改为 5 列等宽网格。
> 3. 移动端沙盘素材条被挤成一行只剩 1 个可见。修复：分类条与素材条改为两行，各自横向滚动。
> 4. **安全相关**：PHQ-9 第 9 题 > 0 但总分落在「平稳」区间时，页面同时显示危机求助区块
>    和「状态平稳」标签，会强化「我没那么严重」的自我说服。修复：该情况下把标签改为
>    「需要优先关注」、主标题改为「先说这一件事」，并把建议列表替换为危机场景专用内容。
> 5. **部署后深层链接白屏**：`base: './'` 导致 `/scales/phq-9` 这类两层子路由的资源被解析到
>    `/scales/assets/`，SPA fallback 返回 HTML，模块脚本 MIME 不符被拒绝执行。
>    首页和单层路由却完全正常，极难在开发时发现。修复：`base: '/'`，并对生产构建
>    直接访问深层链接做了完整回归（46 次渲染 0 问题）。

## 附录 B：部署

产物是纯静态文件，可直接部署到任意静态托管：

```bash
npm run build
# 将 dist/ 目录上传即可
```

> ⚠️ 本站使用 `BrowserRouter`。若部署到静态托管，需配置**所有路径回退到 `index.html`**
> （Nginx `try_files $uri /index.html;`、Vercel/Netlify 的 SPA rewrite 规则）。
> 若无法配置回退，可将 `main.tsx` 中的 `BrowserRouter` 换成 `HashRouter`。
>
> ⚠️ **两个必须实测的点**：
> 1. 部署后**直接访问** `/scales/phq-9` 这类两层子路由（不要从首页点进去），确认不白屏。
>    本站 `base` 为 `'/'`；若改成 `'./'`，浏览器会把资源解析成 `/scales/assets/*.js`，
>    在 SPA fallback 下拿到 `text/html`，模块脚本被拒绝执行 —— 整页白屏，而首页和
>    单层路由却完全正常（本项目开发中真实踩过一次）。
> 2. 若部署在**子目录**（如 `example.com/xinyu/`），需同时修改 `vite.config.ts` 的
>    `base` 为 `'/xinyu/'` 与路由的 `basename="/xinyu"`，否则同样白屏。
