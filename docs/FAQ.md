## 一、数据在哪、会不会被上传

### 我的沙盘记录存在哪里？

**只存在你这台设备的浏览器里**，两个地方：

| 存储 | 存什么 | 容量上限 |
| --- | --- | --- |
| `localStorage` | 会话列表、偏好、量表结果、来访者档案（姓名等**由你自己决定填不填**） | 约 5MB |
| `IndexedDB` | 沙面大块数据、缩略图（比 localStorage 适合存二进制） | 通常几百 MB |

**没有任何服务器。** 项目是纯前端，没有后端代码，
`npm run check` 里有一条 `bundle-budget.mjs` 专门守住"不许引入联网依赖"。

你可以自己验证：打开 DevTools → Network，做任何操作，
除了加载静态资源之外**不会产生任何请求**。

### 那我换台电脑、或者清了浏览器缓存，数据是不是就没了？

**是的，而且这是设计取舍，不是 bug。**

浏览器存储绑定在「这台设备 + 这个浏览器 + 这个域名」上。以下操作都会导致数据丢失：

- 清理浏览器数据 / 使用"无痕模式"
- 换浏览器、换设备
- 换部署地址（`localhost:5173` 和 `example.com` 是两个独立存储）

**所以：重要的记录请主动导出。** 沙盘页和记录单都有导出入口
（`.sandplay.json` 文件 / 打印成 PDF）。

### 导出文件里有什么？会不会泄露隐私？

`.sandplay.json` 包含：沙面高度数据、摆件位置与注释、事件流、统计。
**不包含任何身份信息**（除非你在"来访者姓名"里自己填了）。

文件名和内容都不带时间戳以外的元数据，也不带设备信息。
如果要把记录给别人（例如督导），建议先用匿名代号替代真实姓名。

## 二、沙盘怎么用

### 「自助模式」和「咨询师模式」有什么区别？

| | 自助模式 | 咨询师模式 |
| --- | --- | --- |
| 面向 | 你自己 | 咨询师在会谈中使用 |
| 档案 | 不需要 | 有来访者列表、可绑定会话 |
| 对比 | 不需要 | 可多会话并排对比 |
| 静默模式 | 可用 | 可用 |

两种模式的数据**存在同一台设备上**，互相能看到（没有账号体系，
所以做不了真正的隔离 —— 见下一节）。

### 静默模式是干什么的？

隐藏界面上的统计数字、事件计数、时间轴刻度。

设计意图：有些来访者看到"你放了 12 个摆件"这类数字会分心，
或者会开始揣测"数字意味着什么"。静默模式让界面只剩沙盘本身。

**它只是不显示，不是不记录** —— 事件流照常写入，封盘后统计照常可看。

### 为什么没有"分析/解读/建议"功能？

**这是红线，不是待办。**

见 [`CONTRACT.md`](./CONTRACT.md) §5.6。给沙盘自动生成解读，在专业上站不住，
在伦理上有风险（可能被当成评估结论使用）。本项目只提供**记录**与**客观统计**
（摆件数量、类别分布、操作时长），不提供任何解释。

### 沙面只能画 32×24 吗？感觉很粗

沙面内部是 **128×96** 的高度场，渲染到屏幕时按网格绘制。

看起来"粗"的地方是**笔刷的平滑策略**：为了在低端设备上保持帧率，
笔刷的落点做了量化。这是 `render-perf.mjs` 门禁守着的取舍
（单帧绘制 p95 ≤ 4ms）。

如果你在性能足够的设备上仍觉得不够精细，欢迎带具体操作序列提 issue。

## 三、沙具与沙具包

### 沙具是什么？是图片文件吗？

**默认的 327 个沙具全部是 Unicode emoji 字符**，不是图片文件。

好处：零网络请求、零授权风险、任何字体渲染都能显示、体积极小。
代价：视觉风格受系统字体影响，不同设备看起来略有差别。

如果你需要自定义图片沙具，用**沙具包**（见下条）。

### 怎么加自己的沙具？

做一个 `symbol-pack/v1` 包，用 CLI 校验后导入。完整教程见
[`SYMBOL_PACK.md`](./SYMBOL_PACK.md) §1.5（有从零开始的例子）。

```bash
# 校验你的包
npx tsx scripts/validate-pack.ts 你的包.symbolpack.json
```

样例文件在 `samples/`：纯字形包、内嵌图片包、以及一个**故意写坏**的包
（用来对照看错误提示长什么样）。

### 导入沙具包会怎样？安全吗？

导入前会经过 `validatePack()` 校验（单一真源在 `src/sandbox/library/packs.ts`）：

- 拒绝超过 2000 个符号的包
- 拒绝超过 200KB 的单张图片 dataURL
- 拒绝非法分类、重复 id、缺失必填字段

**图片不会被上传或执行**，只作为 dataURL 存进 `localStorage` 并渲染到 canvas。
但要注意：`<img>` 加载的 dataURL 仍是"外来内容"，
**只导入你信任来源的包**。

### 沙具包有授权问题吗？

内置沙具是 emoji，不涉及图片授权。**你导入的沙具包由你自己负责授权合规** ——
包里的 manifest 有 `license` 字段，请如实填写。

## 四、数据格式与外部工具

### `.sandplay.json` 的规范在哪？

[`FORMAT.md`](./FORMAT.md)，配套 JSON Schema 在 `public/schema/`。

### 别的程序能读我的沙盘文件吗？

能。这是格式规范存在的目的。校验器是独立 CLI：

```bash
npx tsx scripts/validate-session.ts 你的文件.sandplay.json
```

### 格式会变吗？我的文件会不会读不了？

格式有版本号（`sandplay-session/v1`）。**旧版本文件会通过迁移函数读取**：

- `isLegacySnapshot()` 判断是不是旧的 `SandboxSnapshot` 结构
- `migrateSnapshot()` 把旧结构转成 `SandSession`
- `coerceSession()` 对任意输入做宽松化解析（读外部文件时用）

三个函数都在 `src/format/migrate.ts`，有单元测试覆盖「旧 v1 快照可读、可迁移」。

### 事件流为什么最多 4000 条？

`MAX_EVENTS = 4000`。超过后**从最早的开始压缩**（把连续的移动合并），
而不是直接丢弃 —— 直接丢会丢摆件，这是一个真实修过的 bug
（见 `events-truncate.test.ts` 的注释）。

一次典型会谈（30–60 分钟）的操作量远低于 4000。

## 五、无障碍与兼容性

### 键盘能用吗？

**能用。** 默认的 2.5D 渲染器下：

- `Tab` 进入沙具库，`Enter` 放入
- `Tab` 进入摆件清单，方向键移动（`Shift` 加速），`Enter` 选中
- 所有交互元素都有可见焦点框

E2E 有 21 项断言覆盖这条流程。

**已知边界**：可选的 3D 渲染器（`three`）没有摆件键盘入口 ——
它是非默认路径，需要 WebGL，本身对辅助技术也不友好。

### 支持哪些浏览器？

开发和验收都在 **Chrome** 上做（E2E / a11y / 视觉回归全用真实 Chrome）。

Firefox 和 Safari **未做逐项验证** —— 这是诚实说明，不是"应该没问题"。
已知风险点：`IndexedDB` 在 Safari 无痕模式下行为不同（代码有降级路径，
`src/lib/idb-fallback.test.ts` 13 项测试覆盖），但整体未验。

### 手机上能用吗？

能用。E2E 有 390px 视口场景，路由健康门禁对**全部 15 条路由**检查了
"手机上不横向溢出"。

**未验证的**：真机上是否稳定 ≥30fps（headless 环境证明不了这个，
`ROADMAP.md` 里明确标为未达成）。

## 六、开发与贡献

### 怎么本地跑起来？

```bash
npm ci
npm run dev
```

### 提交前必须跑什么？

```bash
npm run check
```

24 个环节，全绿才算过。**注意 `npm run e2e` 不会自动构建** ——
它跑的是现有的 `dist/`，所以要先 `npx vite build`。

细节见 [`CONTRIBUTING.md`](../CONTRIBUTING.md)。

### 为什么门禁这么多、这么严？

因为很多门禁是为了抓**曾经真实发生过的缺陷**，不是为了凑数。
两个典型：

- 事件流截断曾经静默丢摆件（放 10 个，压 4005 条事件后剩 0 个）
- 键盘操作曾经只有"能听到"没有"能操作"

每条门禁的注释里都写了它防的是什么。想删一条门禁前，
先读它的注释和对应的自测。

### 我改了什么会让某个门禁变红，但我不理解为什么

先找它的**自测**（`scripts/audit/*-self-test.mjs`）——
那些自测会故意破坏代码，证明门禁真的能红。
读一遍就知道它到底在守什么。

如果仍然认为门禁判断错了，那是门禁的 bug，请提 issue。
